## Phase3 — TypeScript/Python bridge

### Task3A: versioned JSONL and physically separate feature/label exporters
Files proposed: lib/poker/export/{features,labels,schema}.ts/tests, scripts/export-decisions.ts, python/data/{schema,loader,features}.py/tests, handoffs/golden/decision-v1.jsonl.
Schema: top level schemaVersion,sourceHash,poolHash,seed,matchId,handId,decisionId,featureBlock,labelBlock. FeatureBlock: observation from actor's current view (own cards,current board,stacks,public commitments,pots,position,blinds,public action history), legalActions, range/equity summaries, and actionTaken as logged behavior metadata. Explicit model input allowlist EXCLUDES actionTaken,reason strings,results,terminal logs,labelBlock,IDs/seed,opponent policy IDs and future board. Publicly revealed cards allowed only if already observable at that decision. Sanitizing a terminal view afterward is forbidden. No raw engine state passed to feature exporter.
LabelBlock in a separate joinable file by decisionId: realized incremental payout/net, optionally hidden holdings/full-information rollout action values, uncertainty and label-policy/horizon IDs. Features cannot import labels; privilege confirmation required before generating privileged labels. Use TS engine for all rollouts. Opponent response labels must be modeled as responding to candidate actions, not frozen observed actions.
Commands: `npm test -- --config vitest.config.mts lib/poker/export`; `node_modules/.bin/vite-node scripts/export-decisions.ts --protocol handoffs/protocols/export-v1.json`; `python -m pytest python/tests/test_data.py`.
Fixed exporter smoke:105101–105102,4hands,6seats, all rotations,<10minutes. Acceptance: strict schema rejects unknown fields; future-card mutation leaves features byte-identical; label shuffle/removal leaves model input identical; sentinel hidden fields rejected; split by seed/hand, never decision row. Python/TS golden numeric features atol1e-6 and categorical equality; deterministic replay match. Kill on any leakage/parity failure. Large collection requires a separate fixed manifest and per-run<=2h.

### Task4B: PyTorch action-value residual MLP and heuristic
Files proposed: python/models/value_mlp.py, python/train.py, python/tests/test_model.py, lib/poker/heuristic-control.ts/tests (research-only opt-in), handoffs/models/value-v1/.
Model:2hidden layers32units ReLU, predicts incremental chip value per legal action from public pot/stack/position/street features, equity+payout SE, public range summaries and action size. Standardization fitted on training only. Mask illegal actions; choose max EV with baseline fallback on invalid outputs. Privileged labels stay solely in loss targets. Seed-level60/20/20train/validation/test split frozen before export; tune only validation. Fixed training seed7,20epochs,batch256,CPU-first; checkpoint chosen by predeclared validation loss only. `python -m python.train --config handoffs/protocols/model-v1.json --output handoffs/models/value-v1`; unit tests `python -m pytest python/tests/test_model.py`. Runtime<=2h; no epoch extension; stop invalid loss/leakage.
Offline gates: held-out seed-macro action-value RMSE at least5%below a constant/baseline predictor; no street RMSE >5%worse; label uncertainty and ranking error reported. Gates are proposed engineering criteria pending owner approval. No simulation if failed.
Heuristic control: opt-in value raise when conservative eligible payout share exceeds70%, no current bet, at least2active players; use legal half-pot raise size, otherwise baseline; no claim threshold is optimal. Same public features, independent tests for legal sizes/sunk costs. This is a minimal control targeting missing aggression; exact equity interpretation in multiway/side pots must be reviewed before freezing. It gets its own arm, not folded into the model.

## Phase6 — preregistered A/B/C profit test

Files: handoffs/protocols/abc-v1.json, handoffs/protocols/abc-v1-runs.json, frozen models/configs/pool, Python analysis. Three arms: model,heuristic,baseline-v1; same scheduled seats/deals/opponents; all arms complete in every seed cluster. Freeze config and model/pool hashes before execution. No model retraining while this test runs.
Hypotheses: primary model-minus-baseline; secondary heuristic-minus-baseline and model-minus-heuristic. Bonferroni3two-sided comparisons: alpha=.05/3; use98.333%simultaneous per-comparison CIs alongside nominal95%CIs. Corrected lower bound>0 establishes superiority; lower bound>=+5bb/100 is required to claim reliable gain of at least5. Important: at true+5,80%power to reject<=0 is NOT80%power to establish>=5; latter needs an assumed true effect>5 (e.g.+10 yields margin5). Owner confirms intended claim before sample size frozen.
